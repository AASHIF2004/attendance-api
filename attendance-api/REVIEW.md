# REVIEW.md

Defects found in the starter `app/main.py`, and how each was fixed.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` | Naive datetimes: PyMongo returns timezone-less values, the code mixes them with `datetime.now()` (server-local) and IST-aware values. | Subtracting naive and aware datetimes raises `TypeError`; on a non-UTC server every instant is shifted. | `MongoClient(tz_aware=True, tzinfo=UTC)`; all instants are UTC-aware internally and converted to epoch ms only at the API edge (`ms_to_dt`, `dt_to_ms`). |
| 2 | `compute_late_minutes` | Builds shift start with `punch_in.replace(hour, minute)` in **UTC**, not on the IST attendance date. The `> 10` test is on already-floored minutes, so 09:40:01 gives 10 -> "not late" (R2 says late). Seconds are not truncated; overnight shifts are ignored. | Shift 09:30, punch-in 09:40:01 IST must return 10, starter returns 0. Any non-UTC punch gives huge or negative values. | New `compute_late_minutes(punch_in, date, shift_start)` uses IST shift start on the record's date and compares **seconds** `> 600`, then `secs // 60`. |
| 3 | `compute_work_hours` | Python `round()` on a float: banker's rounding plus binary float error (R4 wants half-up). | 0.005 h (18 s) -> `0.0`, expected `0.01`. | `Decimal(secs)/3600` quantized `ROUND_HALF_UP`. |
| 4 | `compute_overtime` | No 30-minute minimum (R3); shift end always on the punch-in date, so overnight shifts give large negative/zero values; `fromisoformat(...).replace(tzinfo=IST)` ignores seconds/overnight. | Shift 18:30, punch-out 18:45 returns 15 (should be 0); 22:00-06:00 shift returns 0 overtime. | Shift end is built from the record date (+1 day when overnight) and overtime is `0` below 30 minutes. |
| 5 | `punch_in` | Unknown employee: `emp` is `None`, so `emp["shift_start"]` raises -> **500** instead of 404. | POST with unknown `emp_code`. | `get_employee_or_404`. |
| 6 | `punch_in` | `datetime.fromtimestamp(ms / 1000)` is server-local and keeps milliseconds; `if body.punched_at` treats a value as falsy; `ts.date()` is not the IST date, and overnight shifts (R1) are ignored. | Punch at 23:30 IST on a UTC server lands on the wrong day. Overnight 02:00 punch gets the wrong `date`. | Epoch ms -> UTC datetime truncated to seconds; IST date and overnight rule in `attendance_date`. |
| 7 | `punch_in` | Check-then-insert race: two simultaneous requests both pass `find_one`. No unique index exists. | Parallel identical punch-ins give two 201s (or one 201 and a duplicate document). | Unique index on `(emp_code, date)`; insert and catch `DuplicateKeyError` -> 409. |
| 8 | `PunchInIn` | `punched_at` accepts floats/strings/seconds; `status` is any string (e.g. `ABSENT`, `foo`). | `punched_at=1783312500` (seconds) is accepted; `status="ABSENT"` is stored. | Strict int in `[1e11, 4102444800000]`; `Literal["PRESENT","WFH","ON_DUTY"]` -> 422. |
| 9 | `punch_in` response | Returns `id` (the ObjectId as a string) and raw datetimes; the contract forbids `_id`/`id` and requires epoch ms. | Response has `"id"` and datetime strings. | `attendance_out()` builds the contract shape. |
| 10 | `create_employee` | Check-then-insert (race), no validation (bad `emp_code`, bad shift format, equal shifts, invalid date), `datetime.now()` is naive local time and is returned as a datetime, not epoch ms. | Concurrent creates both succeed; `emp_code="abc"` accepted. | Pydantic constraints (regex, lengths, real date, `shift_start != shift_end`), unique index + `DuplicateKeyError` -> 409, UTC `created_at`, `employee_out`. |
| 11 | `list_employees` | `skip = page * page_size` skips the first page; `total` ignores the department filter; no sort; `page`/`page_size` unvalidated (0, negative, huge). | `page=1` returns the 2nd page; `total` is the same for any department. | `skip=(page-1)*page_size`, `count_documents(q)`, sort by `emp_code`, `Query(ge=1, le=100)`. |
| 12 | `list_attendance` | Loads the whole filtered collection into memory, sorts in Python (no tie-break on `emp_code`), paginates in a slice; no indexes. | 100k documents: slow and memory-heavy. | Sort/skip/limit in MongoDB, `(date desc, emp_code asc)`, indexes for each filter shape. |
| 13 | `list_attendance` | No validation of `date_from`/`date_to`/`status`/paging; `date_from > date_to` not rejected; returns `_id` as `id` and raw datetimes; missing `half_day`/`history` not defaulted. | `date_from=abc`, `status=foo`, `page_size=100000`. | Date format and order checks (422), `Literal` status, bounded paging, `attendance_out` applies defaults. |
| 13b | `list_attendance` / `list_employees` totals | `count_documents({})` on an empty filter scans the collection. | Slow `total` on 100k docs. | Empty filter -> `estimated_document_count()`. |
| 14 | `GET /health` | Always returns 200 even if MongoDB is down. | Stop Mongo; health still says ok. | Pings the database, 503 on failure. |
| 15 | Startup | No indexes at all; nothing at startup. | Explain shows `COLLSCAN`. | `create_indexes()` on startup (idempotent). |

**Looked at and kept:** `load_dotenv()` (it does not override real environment variables, which is what the contract wants); the `IST` fixed-offset constant (IST has no DST); `health` route path; returning `emp_code`-based identity (no `_id` use).
